# 04_reports — 발표 및 제출 자료

## 1. 개요

팀 수행계획서 이후의 중간 발표, 최종보고서, 최종 발표자료와 제출 상태를 관리합니다. 보고서의 주장은 데이터 및 실험 기록에 근거하여 작성합니다.

## 2. 작업 내용

- 중간 발표자료에는 데이터 구성, 초기 모델 성능, 손글씨 성능 저하, 원인 분석, 진행 상황과 추가 계획을 담습니다.
- 중간 발표에서 받은 질문과 피드백을 기록하고 후속 작업에 반영합니다.
- 최종보고서에는 프로젝트 목표, 역할 분담과 진행 이력, 데이터 분석, 모델 선정·최적화, 개선 전후 비교와 결론을 포함합니다.
- Accuracy·Macro F1, 학습시간·자동 Pipeline 처리시간·예측시간, 개발용 데이터의 오분류 사례와 Learning Curve를 이용해 개선 근거를 검증합니다. Epoch 개념이 없는 모델에 Epoch별 곡선을 임의로 만들지 않습니다.
- 제출 시 보고서·발표자료·실행 결과가 포함된 .ipynb를 한 ZIP으로, 용도별 데이터셋을 다른 ZIP으로 묶습니다.
- 최종 발표는 팀원 모두가 맡은 작업과 결과를 설명할 수 있도록 준비합니다.

## 6. 향후 계획

- 중간 발표 PDF는 원본 그대로 등록 완료. 향후 교수님 피드백 및 추가 실험의 실제 완료 여부를 별도 기록합니다.
- 4명 모두 데이터·오류 분석, 전처리·증강 가설 실험을 직접 수행하고 자신의 실측 그림·CSV·Notebook을 최종보고서에 연결합니다.
- Final Notebook에는 모델 선정·Normal/Combined·Pipeline/증강·최적화 과정, Actual/Validation 지표·시간·Learning Curve 및 실패 사례를 보존합니다.
- 제출 전 보고서·발표자료·Notebook·데이터 ZIP 분류, 개인별 기여도 총합 100% 및 수행일지 일치 여부를 점검합니다.

## 7. 교수님 최신 답변과 연구 흐름도 (2026-11-10)

[확정 연구 흐름도](../01_project/RESEARCH_FLOW.md): **Normal과 Combined 각각 최적 모델 1개 선정 → 최적 모델 2개 동결 → Original Test 16,000장 → 교수님 1차 Test**. 만족하면 보고서 제출, 부족하면 **1차를 Validation으로 전환**해 개선하고 **2차 Test 1회** 최종 보고.

| 데이터 | 최종보고서에 기재할 분석 | 평가 구분 |
|---|---|---|
| 공식 개발 Validation 19,200장 | Normal/Combined 각각 최적화 과정, 모델별 Accuracy·Macro F1·Learning Curve·시간 | 개발용 |
| 팀 Hand-made 2,560장 | Confusion Matrix·오분류/이미지 특성, Pipeline/증강 전후 및 작성자 Group CV 가능 | 개발용. 학습 이미지/작성자 누출 금지 |
| 공식 **Original Test 16,000장** | MNIST 숫자 Test 10,000 + EMNIST A–F Test 6,000. 두 고정 모델 평가 | 독립 공식 평가, 튜닝에 활용 금지 |
| **교수님 1차 Hand-made** | 최초 고정 모델 2개를 Test; 만족하면 그대로 보고 | **부족할 때에만** Validation 전환·오류 분석·추가 최적화 가능. 전환 이후에는 독립 Test 아님 |
| **교수님 2차 Hand-made** | 1차 보완 경로에서 재고정한 모델의 결과 | **최종 Test 단 1회**, 이후 튜닝 금지 |

**모델 비교의 기본 결과:** Normal Optimized vs Combined Optimized의 Original Test, 1차 Hand-made Test 점수를 함께 제시하고, 1차를 개발용 Validation으로 활용했는지 여부를 명시한다. 2차에 도달한 경우에는 해당 최종 모델 버전과 2차 결과를 정확히 연결해 보고한다. 평가 단계별 모델 버전이 달랐다면 이전 버전의 점수를 최종 버전 점수라고 표시하지 않는다.

**연구 기록:** 데이터 오류 분석 → 전처리·증강 → Normal/Combined 각각 독립 최적화 → 두 모델 비교의 실험 조건·시간·실측 결과·실패 사례를 Notebook과 로그에 보존한다. 팀원별 구체 업무 분담은 팀장이 별도로 작성한다. 중간 발표 PDF 및 실험 CSV·NPZ 원본은 변경하지 않는다.
