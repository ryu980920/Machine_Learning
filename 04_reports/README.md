# 04_reports — 발표 및 제출 자료

## 1. 개요

팀 수행계획서 이후의 중간 발표, 최종보고서, 최종 발표자료와 제출 상태를 관리합니다. 보고서의 주장은 데이터 및 실험 기록에 근거하여 작성합니다.

## 2. 작업 내용

- 중간 발표자료에는 데이터 구성, 초기 모델 성능, 손글씨 성능 저하, 원인 분석, 진행 상황과 추가 계획을 담습니다.
- 중간 발표에서 받은 질문과 피드백을 기록하고 후속 작업에 반영합니다.
- 최종보고서에는 프로젝트 목표, 역할 분담과 진행 이력, 데이터 분석, 모델 선정·최적화, 개선 전후 비교와 결론을 포함합니다.
- Accuracy·Macro F1, 학습시간·자동 Pipeline 처리시간·예측시간, 개발용 데이터의 오분류 사례와 Learning Curve를 이용해 개선 근거를 검증합니다. Epoch 개념이 없는 모델에 Epoch별 곡선을 임의로 만들지 않습니다.
- 제출 시 보고서·발표자료·실행 결과가 포함된 .ipynb를 한 ZIP으로, 용도별 데이터셋을 다른 ZIP으로 묶습니다.
- 최종 발표는 팀원 모두가 맡은 작업과 결과를 설명할 수 있도록 준비합니다.

## 5. 특이사항 및 시행착오

문제가 발생하거나 새로운 방법을 시도하면 아래 **공통 양식**을 복사하여 기록 번호를 늘려 작성합니다. 같은 문제를 다시 시도한 경우에도 앞선 기록을 삭제하지 않습니다. 원인에 대한 가설과 검증된 사실을 구분합니다.

```markdown
### 기록 #001 — [제목]

- **날짜:** YYYY-MM-DD
- **담당자:** [이름]
- **상태:** 진행 중 / 해결 / 보류

**문제:** [발생한 문제 또는 확인해야 할 특이사항]

**원인:** [확인한 원인. 확인 전이라면 '추정'으로 표시]

**시도한 방법:** [어떤 조건·방법을 변경하거나 확인했는지]

**결과:** [수정 전후의 관찰 결과와 수치·이미지 등 검증 근거]

**다음 작업:** [추가 확인 또는 개선할 일]

**관련 자료:** [관련 파일 경로, Notebook, CSV, 그래프 또는 링크]
```

## 6. 향후 계획

- 중간 발표 PDF는 원본 그대로 등록 완료. 향후 교수님 피드백 및 추가 실험의 실제 완료 여부를 별도 기록합니다.
- 4명 모두 데이터·오류 분석, 전처리·증강 가설 실험을 직접 수행하고 자신의 실측 그림·CSV·Notebook을 최종보고서에 연결합니다.
- Final Notebook에는 모델 선정·Normal/Combined·Pipeline/증강·최적화 과정, Actual/Validation 지표·시간·Learning Curve 및 실패 사례를 보존합니다.
- 제출 전 보고서·발표자료·Notebook·데이터 ZIP 분류, 개인별 기여도 총합 100% 및 수행일지 일치 여부를 점검합니다.

## 7. 교수님 최신 지침: 최종 분석과 독립 Test 구분 (2026-11-10)

| 구분 | 기록할 내용 | 반드시 지킬 경계 |
|---|---|---|
| 공식 개발 Validation 19,200장 | Normal·Combined·전처리·증강·하이퍼파라미터 전후 Accuracy·Macro F1, 오분류/분포 | 개발용 점수로 표기 |
| 개발용 손글씨(기존 2,560장 및 신규 Validation 권장 640장) | 클래스·작성자·밝기·크기·중심·기울기·획 굵기 등 오류/특성 분석 및 개선 전후 | Training과 평가 샘플/작성자가 겹치지 않도록 기록 |
| 공식 Original Test 16,000장 | 고정 최종 모델의 Original 데이터 평가 및 Normal/Combined 비교 | Test를 보고 튜닝하지 않음 |
| 신규 독립 손글씨 Test 권장 640장 | **선택 사항** 자체 평가 | 필수 과제가 아니며 확보되지 않았다면 실측값을 만들지 않음 |
| **교수님 1차 Hand-made Test** | 고정 모델+자동 Pipeline의 **전체 성능만 확인** | **원본 이미지·개별 오분류·특정 클래스/분포·Confusion Matrix 분석, 맞춤 수정 금지**. 충분하면 종료 |
| **교수님 2차 Hand-made Test (조건부)** | 1차가 부족할 때 기존 개발 자료로만 개선한 모델의 전체 최종 성능 확인 | **1차 Test 자료는 개선에 사용하지 않으며**, 2차 이후 평가 종료 |

**자동 전처리 Pipeline은 모델의 일부**로서 추론 시 동일하게 작동할 수 있다. 이것은 교수님이 제공한 Test 이미지를 사람이 별도로 회전·리사이즈·교체·수정하는 행위와 다르다. Cleaning은 교수님이 명시적으로 허용한 최소 범위에서만 한다. 1차/2차 Test 자료 자체를 분석한 근거를 작성하지 않는다.

**전원 참여 보고:** 네 명 모두 개발용 오류·Original/Hand-made 데이터 차이·자동 Pipeline/증강 시도와 전후 성능을 맡아 수행한다. 중간 발표자료 제작과 모델 하이퍼파라미터 변경만으로 한 명의 전체 작업을 대체하지 않으며, 각자 실제 기여가 [주차별 실험 로그](../03_experiments/README.md)에 연결되도록 한다. 이름별 전문 집중 영역은 [병렬 작업계획](../01_project/TEAM_PARALLEL_WORKPLAN.md) 참조(아직 담당 확정·수행 완료 아님).

모델 선택·손글씨 추가·데이터 전처리·증강 등의 **변경 변수별 효과를 분리해 비교**하고, Learning Curve·학습/추론시간을 실제 Notebook 출력과 연결한다. 기존 중간 발표 PDF는 변경 없이 보존한다.
