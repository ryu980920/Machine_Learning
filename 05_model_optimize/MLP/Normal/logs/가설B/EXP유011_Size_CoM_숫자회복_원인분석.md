## 1. 연구 질문과 사전 실험 계획

**질문:** 왜 Size-only에서 Hand-made 숫자 정확도가 36.4583%였는데, Size→CoM에서 84.0625%로 회복되었는가?

**가설 2:** Size-only 변환 후 남는 입력의 CoM/픽셀 좌표 불일치가 숫자 분류에 불리했고, CoM 재정렬과 그 입력에 맞춘 모델 재학습이 이 손실을 완화했다.

**실험 구분:** 과거 실험의 Size→CoM 모델과 Size-only 모델의 대각선 정확도 비교는 **전처리 학습·평가가 동시에 달라지므로** 원인을 분리하지 못한다. 이번에는 이전 EXP유006에서 실제 학습했던 CoM, Size-only, Size→CoM **9개 모델(Seed 42·43·44)**을 보관된 Joblib 체크포인트 그대로 로드하고 해시(SHA256)와 기존 정답 건수가 같음을 확인했다. **재학습 없이**, 모든 모델을 평가 입력 `raw`, `CoM`, `Size`, `Size→CoM`의 4개 경우에 각각 적용하여 교차평가했다.

공식 Train76,800/Validation19,200/Hand-made2,560. 공식 Train 기준 Size 목표는 BBox 긴 변 20px, threshold32, bilinear affine; CoM은 threshold32 목표(13.5,13.5) 정수 이동. 공식 Original Test·교수님 Test 사용 안 함.

## 2. 기존 모델 고정 × 평가 입력 교차 실측

**Hand-made 숫자·문자 정확도(%, Seed 3개 평균).**

| 고정 학습 모델 | 평가 입력 | 숫자 | 문자 | 공식 Val |
|---|---|---:|---:|---:|
| **CoM 모델** | CoM (기준) | **84.4167** | 66.4931 | 97.0521 |
| CoM 모델 | Size | 81.3125 | 39.8611 | 76.5694 |
| CoM 모델 | Size→CoM | **91.4792** | 55.3472 | 81.9045 |
| **Size 모델** | Size (기준) | **36.4583** | 94.2014 | 96.6858 |
| Size 모델 | Size→CoM | **73.8125** | 69.7222 | 86.4080 |
| **Size→CoM 모델** | Size | 72.2708 | 77.2917 | 91.9983 |
| Size→CoM 모델 | Size→CoM (기준) | **84.0625** | **91.7708** | 96.0608 |

위의 학습·평가 불일치 모델은 **반사실적 진단용**이며, 공식 Val이 크게 떨어질 수 있어 최종 추론 성능 비교 대조군으로 간주하지 않는다.

## 3. 숫자 회복 폭을 두 단계로 분리

기존 대각선 비교에서 Size-only 숫자 **36.4583% → Size→CoM 84.0625%**는 **+47.6042%p**였다.

**모델 고정 경로:**

1. **Size-only 모델을 그대로 고정하고 평가 입력만 Size→CoM으로 변경:** 36.4583 → 73.8125% = **+37.3542%p**.
2. **같은 Size→CoM 평가 입력에 대해 Size-only 모델 대신 Size→CoM 학습 모델을 사용:** 73.8125 → 84.0625% = **+10.2500%p**.

숫자의 총 변화 +47.6042%p는 위 **특정 경로에서** +37.3542 +10.2500%p로 분해할 수 있다. 그러나 이 수치를 일반적인 독립 기여도라고 해석해서는 안 된다. 반대 순서에서는 동일 Size 평가 입력에서 **재학습 효과 +35.8125%p**(36.4583→72.2708), 고정 Size→CoM 모델의 입력 CoM 효과는 **+11.7917%p**(72.2708→84.0625)다. **학습 방식과 평가 입력의 강한 상호작용이 확인됐다.**

문자에는 상반된 영향이 있었다. Size-only 모델에서 입력만 CoM으로 정렬하면 문자 94.2014% → 69.7222%(**−24.4792%p**)로 감소했지만, Size→CoM 입력에 맞춘 재학습 모델은 91.7708%로 회복한다(**+22.0486%p**). 즉, 문자 유지에는 단순 정렬뿐 아니라 **정렬된 입력으로 재학습하는 것이 중요**하다.

## 4. 크기 정규화와 CoM에 따른 오류 방향 역전

**원래 학습 방식과 같은 평가 전처리(대각선), 실제 그룹 간 잘못 예측한 비율, 3 Seed 평균.**

| 조건 | 실제 숫자 → 문자 예측 | 실제 문자 → 숫자 예측 |
|---|---:|---:|
| CoM-only | **8.10%** | **31.56%** |
| Size-only | **60.23%** | **0.66%** |
| Size→CoM | **9.31%** | **4.41%** |

분류 실패가 Size-only에서 숫자→문자 쪽으로 크게 편향됐고 CoM-only에서는 문자→숫자 쪽으로 편향됐다. Size→CoM에서는 양방향 오류 비율이 크게 줄어들었다.

**대표 혼동쌍 오답 건수(Seed당 평균, 각 실제 클래스 160장).**

| 실제 → 오답 | CoM-only | Size-only | Size→CoM |
|---|---:|---:|---:|
| B→8 | 72.67 | 1.33 | 11.33 |
| 8→B | 33.33 | **97.00** | 37.00 |
| D→0 | 64.67 | 1.67 | 16.33 |
| 0→D | 25.00 | **78.67** | 18.00 |
| F→5 | 13.00 | 0.00 | 0.33 |
| 5→F | 11.33 | **76.33** | 13.00 |

이는 문자/숫자 격차가 특정 방향의 대량 오분류와 직접 연결되어 있음을 보여준다.

## 5. 실제 중심 이동량·동일 이미지 복구

| 항목 | 실제 평균 |
|---|---:|
| Size-only 처리 후 CoM 중심거리 | 1.3468px |
| Size→CoM 이후 중심거리 | 0.3800px |
| CoM 재정렬 시 실제 이동거리 | 1.3399px |
| 재정렬 이동이 0이 아닌 이미지 비율 | 81.52% |
| 질량 유지 비율(평균, Size→CoM / Size-only) | 99.988% |

각 Seed와 이미지별로 복구·신규 오답을 대응 비교했다. **Size-only 대각선 모델 → Size→CoM 대각선 모델**에서 숫자는 Seed당 평균 **781.33장 정답 전환 / 19.67장 신규 오답**으로 순증 **761.67장(1,600장 중 47.6042%p)**, 문자는 정답 29.33장 전환 / 신규 오답 52.67장으로 순감 23.33장(−2.4306%p)이었다.

정답으로 복구된 이미지의 CoM 이동거리 평균 1.5297px는 신규 오답 이미지의 1.0624px보다 컸다. 다만 이는 복구된 이미지와 악화된 이미지의 관찰 차이이며, 이동거리만이 원인이라는 뜻은 아니다.

## 6. 가설 2 판정 및 한계

**판정: 모델을 고정한 입력 변경만으로 숫자 급락이 상당 부분 회복된다는 점을 직접 확인. 추가로 학습된 가중치의 영향도 큼.**

- CoM 정렬이 숫자 예측에 중요하다는 가설은 실측으로 지지됨.
- 그러나 CoM 이동은 이미지 일부의 zero-fill 및 픽셀 잘림을 동반할 수 있어 '좌표 변화만의 순수 효과'라고 과장하면 안 된다.
- 핵심은 **입력 중심 보정과 그에 맞춘 모델 학습의 조합**. Size-only 대각선과 Size→CoM 대각선을 빼서 CoM 단독 효과라고 설명하는 것은 잘못.
- 교차 입력은 Training과 달라지는 out-of-distribution 영향을 포함한다. 특히 Official Val 수치 하락과 함께 보고해야 한다.
- 전수 대응 CSV와 모델별 오류 방향은 기존 모델 9개를 SHA256로 검증한 동일 실행에서 생성했다.
