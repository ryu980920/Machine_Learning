# EXP-CMB-004 · 01 계획 — Geometry Normalization

> **실험 ID: EXP-CMB-004 · 상태: 사전등록 / 실측 미실시**
>
> **연구 질문:** Bounding Box 기반 **크기 정규화(Size)**와 **CoM 중심 정렬(Center)** 중 어떤 방법이 어떤 오분류를 개선/악화하는가? 실제 크기·중심 변화, 오류 전환, 클래스 점수, 작성자 차이를 통해 이유를 설명할 수 있는가?
>
> **통과 기준은 특정 Accuracy나 Macro F1 수치에 도달하는 것이 아니다.** '어느 방법이 왜 효과적인지, 또는 둘 다 효과가 부족한 이유'를 실제 반례까지 포함해 근거로 설명할 수 있어야 실험을 종료한다.

## 1. 선행 근거와 정확한 방법 구분

- Baseline: Combined OOF 81.2500%, Macro F1 0.812043, 0↔D 오류 59건, 8↔B 오류 53건.
- EXP-CMB-002: Writer 43의 8→B에서 너비·잉크 증가, Writer 41의 D→0에서 오른쪽 CoM 차이.
- EXP-CMB-003: 기존 모델에만 적용한 95% 고정 축소는 OOF +2.6172%p이지만 43번에 개선 집중, 공식 Validation 저하.
- **Normal EXP유004의 Bounding Box 방법은 '크기 정규화'가 아니라 'Bounding Box 중심 정렬'이었다.** Size-only는 이번 Combined에서 새로 도입하는 독립적인 조작이다.

## 2. 독립 실험 조건 (모든 변경 후보는 새 4-Fold MLP로 재학습)

| 조건 | 방법 | 목적 |
|---|---|---|
| A | 원본 EXP-CMB-001 Baseline | 기존 실측 참조, 재학습하지 않음 |
| B | BBox 중심 정렬 | Normal에서 쓰던 center-only 대조 |
| C | BBox 크기 정규화 | **첫 번째 주요 방법**: BBox의 긴 변 길이를 공식 Training 중앙값에 맞춰 크기만 변경 |
| D | CoM 중심 정렬 | **두 번째 주요 방법**: 밝기 가중 중심을 (13.5,13.5)로 이동 |
| E | BBox 크기 정규화 + CoM 중심 정렬 | 두 방법의 결합·상호작용 확인 |

- 전경 Threshold=32/255, 목표 좌표=(13.5,13.5). B/D의 정렬은 Normal과 동일한 정수 픽셀 이동/zero-fill/no-wrap.
- C의 목표 크기는 해당 공식 Training 76,800장 이미지의 전경 Bounding Box **긴 변의 중앙값**으로 결정한다. 보류 작성자, 공식 Validation, 클래스 라벨을 참고해 목표 크기를 선택하지 않는다.
- C의 크기 조정은 BBox 중심을 기준으로 균등 비율 X/Y 확대·축소하며 bilinear 보간과 0 채움을 사용한다. 부수적인 중심·획 질량 변화도 따로 기록한다.
- E는 C 적용 후 D 정렬. B는 C와 D를 비교할 때 중심 정의 자체의 차이를 검토하는 참고 대조다.

## 3. 공통 통제 및 데이터 누출 방지

- Official Train 76,800 / Dev Validation 19,200 기존 분할 고정.
- Writer 41/42/43/44 Leave-One-Writer-Out: 각 Fold Train = Official 76,800 + 다른 작성자 1,920, OOF Held-out 640.
- MLPClassifier(random_state=42), PixelScaler255, 입력 순서·레이블·나머지 학습 설정 고정.
- 전처리는 **Train·공식 Dev Validation·Hand-made Held-out 모두 동일**하게 적용. Fold 사이 가중치 재활용 금지.
- 공식 Original Test와 교수님 Final Test **사용 금지**. EXP-CMB-001~003의 원본 모델·CSV·로그는 변경하지 않는다.

## 4. 사전에 고정하는 통과 기준 — 설명 가능성

**정확도 +2%p 같은 정량 합격선은 설정하지 않는다.** 아래 여섯 검증을 모두 완료해 두 방법을 비교하고 근거로 판정을 내려야 한다.

1. **조작 자체 검증:** Size는 긴 변의 분산을 낮추는가? CoM은 중심 오차를 줄이는가? 중심·크기·잉크 질량 손실 등 의도하지 않은 변화도 실제로 측정한다.
2. **공정한 성능 비교:** 4-Fold OOF Accuracy/Macro Precision/Recall/F1, 작성자·숫자/문자·클래스별 결과, 공식 개발 Validation, Loss Curve·Iteration, 전처리/학습/추론 비용 비교.
3. **핵심 혼동 방향 분해:** 0→D, D→0, 8→B, B→8을 작성자별·방향별로 집계하며 오류 교정과 새 오답을 원본 2,560장에 대해 대응 비교한다.
4. **효과의 작동 근거:** 크기·CoM 변화량, 실제 정오답 전환, 정답−경쟁 클래스 Logit Margin을 동일 이미지에 연결한다. 조작량이 거의 0인 이미지를 대조해 바뀐 이미지에서 효과가 집중되는지 본다.
5. **반례·부작용:** 특정 작성자/숫자/문자만 개선되는지, 오답이 다른 클래스로 옮겨가는지, 공식 Validation이나 이미지 획이 손실되는지 분리해 설명한다.
6. **재현 가능성:** SHA·기존 OOF·Fold·seed·train/val 동일 전처리·학습 반복 횟수·Loss·시간·실제 그림과 표를 보존한다.

## 5. 연구 판정(숫자 하한 없음)

- **Size 우세:** C의 개선·악화 방향을 실제 크기 변화에 연결해 D 대비 상대적 우위를 설명 가능.
- **CoM 우세:** D의 개선·악화 방향을 실제 CoM 변화에 연결해 C 대비 상대적 우위를 설명 가능.
- **둘 다 조건부 효과:** 작성자/클래스·혼동 방향에 따라 기전이 다르고 E의 추가/상쇄 효과까지 설명 가능.
- **둘 다 효과 부족:** 두 방법 모두 목표 오류를 해결하지 못하거나 손실이 크다는 것을 반례 포함 정량 근거로 설명 가능.
- **판정 보류:** 차이 또는 원인 근거 부족. **EXP-CMB-004 안에서 분석 보강, 다음 실험으로 넘어가지 않음.**

실험 '통과'는 **설명 목적 달성**이며, 최종 Pipeline 채택·새 작성자 일반화 증명과 별개다. 개발용 작성자 OOF 반복 선택 과적합의 한계를 기록한다.
