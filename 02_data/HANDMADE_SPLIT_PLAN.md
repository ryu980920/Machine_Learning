# Original·Hand-made 데이터 활용 및 Test 분리 운영 (2026-11-10 수정)

## 1. 실제 확보한 데이터와 제안 데이터

| 데이터 | 수량 | 상태 및 역할 |
|---|---:|---|
| MNIST·EMNIST 공식 Training | **96,000장** | 확보. 내부 고정 Train **76,800** + Validation **19,200**. Normal/Combined의 공식 데이터 개발 기준 |
| MNIST·EMNIST 공식 Original Test | **16,000장** | 확보·최종 평가 전 보존. 숫자 10,000 + A–F 각 1,000 = 문자 6,000. 교수님 구두 분할 설명과 일치 |
| 기존 팀원 Hand-made (41~44번) | **2,560장** | 확보·이미 탐색 평가. **학습·검증·오류 분석 가능**, Combined 편입은 효과 측정 후 판단 |
| 추가 신규 Hand-made Validation | **640장 제안** | 신규 작성자 8명×80장 권장안, **수집 전/수량 미확정**, 개발용 |
| 추가 신규 Hand-made Test | **640장 선택** | 다른 8명×80장 권장안, 독립 자체 평가를 원할 때만 수집. **교수 지정 필수 아님** |
| 교수님 1차 Hand-made | 배포에 따름 | **외부 Test 전용**, 모델·전처리 고정 후 성능 확인 |
| 교수님 2차 Hand-made | 배포에 따름 | **조건부 외부 Test**, 1차 성능 충분하면 생략 가능 |

MNIST 0–9 60,000 Training·10,000 Test, EMNIST A–F **각 6,000 Training·1,000 Test**가 교수님 구두 설명의 기본 구성이다. 현재 v3 112,000장은 이 분할에 맞춰 준비했다. 그중 **공식 Training 96,000장 내부 76,800/19,200** 분할은 W02 Baseline 재현 조건이므로 변경 없이 유지한다.

## 2. 기존 Hand-made 2,560장의 활용

교수님에 따르면 팀원 작성 자료는 초기에 성능을 평가한 후 반복 개선을 수행할 수 있고, 학습 및 Validation에도 활용 가능하다. 그러나 평가를 보고 모델을 수정했다면 **완전히 미사용인 독립 Test라고 부르지 않는다**.

**Normal vs Combined 통제 비교**

- Normal: 공식 Train **76,800장만** 학습.
- Combined 후보: 동일 공식 Train 76,800장에 기존 Hand-made 중 **미리 정한 학습용 샘플**을 추가. 전체 2,560장을 포함할 수 있는 경우는 **평가용이 별도로 확보되었을 때만**이다.
- 모델·학습 설정·스케일링·전처리 Pipeline·Validation 이미지를 동일하게 고정하여 **데이터 추가의 효과만** 비교한다.
- 둘 다 같은 **공식 Validation 19,200장**과 **개발용 손글씨 Validation**에서 Accuracy·Macro F1·클래스/작성자별 성능 및 시간 평가.
- 신규 작성자 Validation 640장 확보 전에는 기존 2,560장 중 **학습에 넣지 않은 작성자 홀드아웃** 등을 개발용으로 사용할 수 있지만, 그 조건에서는 Combined 학습 이미지 수가 **2,560장보다 적어진다**. 보류 샘플을 학습에 쓰지 않는다.

새 작성자 Validation이 있으면 학습·Validation·Test 간 작성자를 분리하는 것이 우선 권장이다. 작성자 정보가 없다면 '작성자 분리 검증'이라고 표현하지 않는다. 데이터 부족으로 자체 Test 수집은 미뤄도 교수님 Test가 최종 외부 평가 역할을 한다.

## 3. 원본 수정과 추론 시 전처리 Pipeline은 다르다

- **개발용 데이터 Cleaning:** 잘못된 레이블·인식 불가능/누락 이미지 등 품질 문제를 기록하고, 원본과 정제본의 관계·수량을 보존. Training에서 다양한 필체를 학습할 수 있도록 augmentation 가능.
- **자동 Pipeline:** 테스트 이미지가 들어올 때도 *사전에 확정한 동일한 규칙*으로 중심 정렬, 크기·기울기·명암 보정 등 적용 가능. Pipeline은 모델의 일부다. 통계량을 학습하는 단계는 **Training만으로 fit**하며 Test의 개별 정답·이미지 특성에 맞추지 않는다.
- **교수님 1·2차 Test 원본:** 임의 이미지 회전·보정·교체·저장 및 특정 오류 원인·Confusion Matrix·클래스별 패턴 분석 금지. 교수님이 허용한 최소 Cleaning을 할 경우에도 사전에 정한 기준을 따르고 이력을 남긴다. 점수는 전체 Accuracy 등 허용된 성능 확인 용도로만 사용한다.
- 1차 전체 점수가 충분하면 종료. 부족하면 **1차 데이터를 일절 재참조하지 않고** 개발용 자료에 근거해 새로운 실험·최적화 후 2차를 평가하고 종료.

## 4. 연구 기록·교차 오염 방지

1. 공식 원본의 증강본은 같은 그룹의 Train/Validation을 넘나들지 않게 유지한다.
2. Validation 반복 사용은 개발 과정이며 별도 독립 Test 결과와 구별한다.
3. 새 작성자 수집 시 클래스별 균형(예시 16종×각 5개)·다양한 평소 필체·펜 종류·작성자 구분 등을 기록한다. **8명×80장 = 640장은 제안**이지 확정이 아니다.
4. 원본/변환 파일, SHA-256, 이미지 형식, 데이터 split, 함수·파라미터, 성능 전후 및 실패 사례를 [실험일지](../03_experiments/EXPERIMENT_TEMPLATE.md)에 연결한다.
5. 어떤 모델도 교수님 1·2차 Test로 학습·튜닝하지 않는다. Final 평가 전 모델과 Pipeline을 동결한다.
