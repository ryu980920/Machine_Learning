## 1. 문제 발견 및 실험 목적

- **현재 상황/발견한 문제:** 프로젝트에서 16개 클래스당 7,000개씩 총 112,000개의 데이터가 필요하였으나 MNIST와 EMNIST의 실제 클래스별 데이터 수가 균등하지 않았다.
- **문제의 근거:** 클래스별 개수 확인 결과 MNIST의 일부 숫자와 EMNIST B, D, E 등 총 10개 클래스에서 데이터가 부족하였다. 목표 대비 부족한 데이터는 총 6,659개였다.
- **이번 실험의 목표:** MNIST와 EMNIST를 동일한 이미지 규격 및 레이블 체계로 통합하고, 부족한 데이터를 보충하여 16개 클래스 모두 7,000개씩 확보한다.

## 2. 원인 분석 및 해결 방법

- **확인된 사실:** MNIST와 EMNIST는 클래스별 원본 이미지 개수가 서로 달랐다. EMNIST 이미지를 처음 시각화했을 때 일부 문자가 정상적인 방향으로 표시되지 않았다.
- **원인 가설:** 데이터셋의 클래스별 표본 수 불균형으로 목표 개수를 충족하지 못하며, EMNIST 이미지의 배열 방향 차이가 시각화 결과에 영향을 준 것으로 판단하였다.
- **선택한 방법:** 각 클래스에서 최대 7,000개의 원본을 추출하고 EMNIST 이미지를 전치하여 방향을 보정하였다. 부족한 데이터는 학습 이미지에 ±1~2픽셀 이동 변환을 적용하여 생성하였다.
- **선택 이유:** 확인 필요. 실제로 적용한 방법은 원본 이미지의 위치를 소폭 변경하는 데이터 증강 방식이다.
- **예상 결과:** 16개 클래스가 각각 7,000개가 되고 전체 데이터셋이 112,000개로 구성될 것으로 예상하였다.

## 3. 실험 조건 및 수행

| 항목 | 실제 적용한 조건 |
| --- | --- |
| 데이터셋 / 버전·파일 경로 | torchvision MNIST, EMNIST byclass / `original_16class_dataset.npz`, `MNIST_EMNIST_16class_112000.npz` |
| Training Set | 최종 101,465개 (원본 94,806개 + 증강 6,659개) |
| Validation Set | 원본 10,535개 |
| 별도 평가 데이터 | 사용 안 함. Hand-made 데이터 미포함 |
| 데이터 분할 방식 | 클래스 비율 유지 계층화 분할, Training 90% / Validation 10% |
| 데이터 분할 Seed | `random_state=42` |
| 모델 / 라이브러리 | 모델 학습 해당 없음 / NumPy, torchvision, Scikit-learn, SciPy |
| 주요 Hyperparameter | 모델 해당 없음 / 클래스 목표 7,000개, Validation 비율 0.1 |
| 모델 학습·초기화 Seed | 해당 없음 |
| 전처리 및 증강 | EMNIST 이미지 전치, 28×28 Grayscale 유지, 학습 원본에 수평·수직 ±1~2픽셀 이동 적용. `scipy.ndimage.shift(order=0, mode="constant", cval=0)` |
| 학습 방식 | 모델 학습 없이 데이터 구성 및 검증 |
| 실행 파일 | `01_dataset_preparation.ipynb` (원문 기재 파일; 이번 등록 자료에 미포함) |

**추가 조건**

- MNIST 원본 Train/Test와 EMNIST 원본 Train/Test를 각각 합친 뒤 필요한 클래스를 추출하였다.
- 원본 클래스별 추출은 `np.random.default_rng(42)`와 비복원추출을 사용하였다.
- 증강 원본 선택 및 이동량 생성에도 `np.random.default_rng(42)`를 사용하였다.
- 최종 Validation 데이터는 증강 이전에 분리하였으며 증강에 사용하지 않았다.
- 통합 레이블은 숫자 0~9에 0~9, 알파벳 A~F에 10~15를 부여하였다.

**변경한 조건(비교 실험인 경우)**

| 구분 | 기존(Baseline) | 이번 실험 |
| --- | --- | --- |
| 데이터 개수 | 105,341개 | 112,000개 |
| 클래스별 표본 수 | 불균등 | 각 7,000개 |
| 증강 데이터 | 없음 | 6,659개 추가 |
| Validation 데이터 | 10,535개 | 10,535개 유지 |

- **동일하게 유지한 조건:** 이미지 크기 28×28, Grayscale 형식, 16개 레이블 체계, 기존 Validation 데이터.
- **실제로 수행한 과정:** ① MNIST와 EMNIST 다운로드 및 클래스별 개수 확인 → ② EMNIST 방향 보정 및 최대 7,000개 원본 추출 → ③ 계층화 분할 및 학습 데이터 증강 → ④ NPZ 저장과 검증.
- **조건의 차이·특이사항:** 최종 데이터셋에 증강 이미지가 포함되어 있다. Validation 데이터는 원본으로 유지하였다. 증강 이미지의 시각적 품질 검증은 아직 완료되지 않았다.

- **관찰된 변화:** 부족한 6,659개를 생성하여 모든 클래스의 데이터 수가 7,000개로 일치하였다. 최종 NPZ 파일에 `X_train`, `y_train`, `X_val`, `y_val` 네 항목이 존재함을 확인하였다.
- **대표 사례 또는 예외:** EMNIST B는 원본 4,526개로 목표 대비 2,474개가 부족하여 가장 많은 데이터 보충이 필요하였다. D는 1,659개, E는 1,215개가 부족하였다.
- **비교 가능성:** 원본과 최종 데이터셋은 동일한 16개 클래스와 이미지 규격을 사용하지만 최종 데이터셋에 증강 데이터가 추가되었다. 모델 정확도 비교는 수행하지 않았다.

## 5. 결과 해석 및 최종 판단

- **최초 문제/질문에 대한 답:** 데이터 개수 목표는 해결하였다. 총 112,000개의 데이터가 저장되었으며 클래스별 개수 검증을 통과하였다.
- **판단 근거:** 최종 NPZ 파일을 다시 불러와 이미지 배열 크기와 레이블별 개수를 확인하였다. 모든 클래스가 7,000개이고 이미지 데이터 타입이 uint8인 것을 검증하였다.
- **한계·추가 확인 사항:** 증강 이미지의 글자 형태와 식별 가능 여부는 아직 시각적으로 검증하지 않았다. 또한 데이터 증강이 모델 인식 정확도에 미치는 영향은 확인되지 않았다.
- **이번 실험의 결론:** 총 112,000개 데이터셋 구성 및 저장을 완료하였다. 추가 이미지 품질 검증을 거친 뒤 모델 학습용 데이터로 전달할 예정이다.

> **최종 확인:** 데이터 개수, 분할 방식, Seed, 전처리 코드, 저장 파일의 배열 구조는 실행 결과와 대조하였다. 증강 이미지의 시각적 품질 및 실험자의 방법 선택 이유는 추가 확인이 필요하다.
