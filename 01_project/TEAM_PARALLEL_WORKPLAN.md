# 전원 참여형 데이터·오류 분석 작업계획 — 4인 병렬 수행안

- 적용 시점: W02 후속 실험부터. **아래 집중 영역은 팀장 운영 제안이며 팀원별 확정 합의/실행 완료 상태가 아님.**
- 공통 목표: 4명 모두 **새로운 필체에 대한 오류 원인 분석 → 자동 전처리/증강 후보 실험 → 동일 조건 비교 → 증거 기반 공유**에 참여한다.
- 교수님 강조사항: 단계별 직렬 분업을 피하고, 같은 주차에 팀원이 서로 다른 가설을 병렬 검증한다. 특정 팀원이 모든 모델 학습·전처리 부담을 독점하지 않는다.

## 1. 모든 팀원이 반드시 수행할 공통 4가지

1. **오류 추출:** 현재 Normal 모델의 개발용 Hand-made 오분류를 자신의 관점에서 최소 한 유형으로 분류한다. 클래스·작성자별 Accuracy/Confusion Matrix와 실제 예시를 연결하고, 교수님 Test는 열어보지 않는다.
2. **데이터 특성 비교:** Original vs Hand-made에서 밝기/대비, 중심 좌표, 외접 크기, 획 밀도·굵기, 기울기, 잘림 중 관련 특징을 **수치나 비교 이미지**로 설명한다. 실제 분석하지 않은 항목은 미실시로 표시.
3. **해결 가설 및 실험:** 고정된 공통 Validation에서 **Raw vs 자동 Pipeline** 또는 **증강 없음 vs 증강 있음** 등 변경 1개의 효과를 비교한다. 같은 평가셋을 쓰고 데이터·Seed·모델 설정의 차이를 기록한다.
4. **검증과 기록:** Accuracy, Macro F1, 대표적인 개선/악화 클래스, 학습·Pipeline·추론 시간, 실패·부작용, 코드/Notebook/CSV 근거를 자신의 주차별 `EXP유001` 형태 로그로 기록한다. 다른 팀원 검토가 가능한 형태로 공유한다.

## 2. 팀원별 병렬 집중 영역 (제안)

| 팀원 | 전원 공통 오류 분석에 더해 집중할 관점 | 전처리·증강 후보(계획, 미실시) | 각자 제출할 근거 |
|---|---|---|---|
| **유용성 (팀장)** | 5개 모델 공통 오분류와 혼동 클래스, Normal/Combined 실험의 비교 공정성·누출 여부 | 입력 중심 정렬·위치 이동 보정, 비교 지표 통합, 후보 Pipeline A | 오류 유형표 + Raw/Pipeline A 비교 + 통합 실험 조건표; 팀 전체 병렬 일정 조정 |
| **김다연** | 작성자별 이미지 명암·배경 차이, 일부 글자 잘림·판독 가능성, 손글씨/공식 분포 차이 | 밝기·대비 정규화 및 배경 노이즈 처리 후보 Pipeline B | 작성자별 품질/분포표 + Raw/Pipeline B 비교 + 발표용 근거 그림 |
| **이선형** | 원본·증강본 간 차이, 기울기·획 굵기·크기·형태 왜곡과 실패 클래스 | 회전·크기·굵기 Training augmentation + 추론용 기울기/크기 정렬 Pipeline C | 원본/증강 이미지·클래스별 변화량 + 누출 검사 + Raw/개선 비교 |
| **곽지호** | 공식 vs Hand-made 데이터 출처·레이블/분포·중복·작성자 분리, 클래스 불균형 | 샘플 비중·학습 데이터 조합·데이터 Cleaning 규칙 및 Pipeline D(필요한 오류 유형 기준) | 출처/클래스별 특성·분할 검증 + Normal/Combined 비교 + 변경 이력 |

**전문 작업을 한 사람에게 고정하지 않는다.** 본인이 주도한 가설이 다른 팀원의 모델에 유효한지 교차 검증한다. 모든 팀원은 자신의 데이터 분석과 성능 실험을 수행하고, 동시에 필요 시 모델 후보도 직접 학습할 수 있다. 팀장 또한 데이터·Pipeline 실험을 직접 수행한다.

## 3. 같은 기간의 병렬 실행 순서

| 회차 | 4명 전원 공동 기준 | 동시 제출물 |
|---|---|---|
| A — 오류 조사 | 현재 공식 Validation과 기존 Hand-made 탐색 평가 결과를 공통 참조, 데이터 버전·평가 지표 일치 | 개인별 오류 카테고리·정량 근거·원인 가설 (미실시 여부 표기) |
| B — 방법 개발 | 각자 1개 이상 **전처리 Pipeline / Augmentation 가설**을 분리 실험; Test 미사용 | 원본/수정 전후 이미지, 함수·순서·범위, Validation 지표, 개선/악화 사례 |
| C — 비교 통합 | 실험별 조건·Seed·Train/Val 분할을 통일, 효과 확인 후 교차 적용 | 팀 공유 비교표, 모델별 재현 가능한 Notebook, 개선 채택/보류 이유 |
| D — 모델 최적화·선정 | 공통 후보 Pipeline과 각 모델 Hyperparameter를 조합, 동일 Validation으로 평가 | 5개 모델 비교·시간·곡선·최종 선정 근거 및 역할별 실적 |

Normal vs Combined **추가 데이터의 효과만** 볼 때는 Pipeline·모델 설정을 고정한다. A/B/C 단계는 필요에 따라 병렬로 겹칠 수 있으나 데이터 누출과 Test 오염은 허용되지 않는다.

## 4. 팀장 점검 체크리스트 및 기여도

- [ ] 4명 모두 **자신이 분석한 오류 유형과 근거**가 있다.
- [ ] 4명 모두 **자신이 제안하거나 비교한 전처리·증강 실험과 결과**가 있다.
- [ ] 실험 조건(데이터 해시·분할·Seed·알고리즘·Pipeline 순서)이 재현 가능하다.
- [ ] 개선 성공뿐 아니라 악화·실패 사례와 근거를 보존했다.
- [ ] 공동 분석을 실시하되 **각자의 실제 기여/담당 단계**는 로그에 구분했다.
- [ ] 교수님 1·2차 Test는 **전체 성능 확인 외 이미지 열람·오류 분석·튜닝에 사용하지 않았다.**
- [ ] 모든 기록에는 실제 실행 상태를 표기했고, 프로젝트 종료 시 **기여도 합계 100%**를 실제 작업과 일치하도록 작성한다. 팀장 기여도 요구 등 교수님 보고 지침을 고려하되 임의 숫자를 사전 확정하지 않는다.
