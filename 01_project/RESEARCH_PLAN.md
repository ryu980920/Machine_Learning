# 2026 머신러닝 팀 프로젝트 — 연구계획 (2026-11-10 최신 지침 반영)

## 1. 목표와 우선순위

대상은 숫자 0–9, 대문자 A–F의 16개 클래스다. 목표는 MNIST·EMNIST에서 잘 학습된 모델이 **처음 보는 필체·위치·기울기·획 굵기**에도 일반화되도록 만드는 것이다.

**우선순위:** (1) 오류 유형과 Original/Hand-made 데이터 분포 차이 분석 → (2) 모든 입력에 동일하게 적용할 자동 전처리 Pipeline·학습용 데이터 증강 검증 → (3) Normal vs Combined 효과 검증·모델별 최적화 → (4) 독립 Test. 높은 Accuracy만으로 완료 처리하지 않고, 원인·가설·실험 설정·전후 결과를 제시한다.

교수님 **최신 구두 지침**은 이전 Project Guide PDF의 1·2차 배포 데이터를 학습에 사용하는 절차보다 우선한다. 1차·2차는 모두 **Test 전용**이다. 본 문서는 교수님이 여러 날에 설명한 내용을 반영한 팀 운영계획이며, 아직 수행하지 않은 실험을 완료로 표시하지 않는다.

## 3. 최신 연구 흐름

| 단계 | 팀 전체의 작업 | 근거·평가 및 종료 조건 |
|---|---|---|
| ① 오류·분포 분석 | **4명 전원** 동일한 데이터/평가 기준으로 Original vs Hand-made의 오분류, 글자 중심·크기·기울기·밝기·획 굵기·극성·레이블/이미지 품질 분석 | 공통 오류 분류표, 클래스·작성자별 비교, 실제 이미지 예시(개발 데이터만), 원인 가설과 측정 근거 |
| ② Normal vs Combined 통제 실험 | 동일 알고리즘·기본 설정·입력 변환·공식 Train 분할로 Original-only와 Hand-made 추가 학습 비교 | 같은 개발용 Hand-made Validation 및 공식 Validation에서 Accuracy·Macro F1·시간 비교; 편입 효과 측정 후 채택 판단 |
| ③ 전처리·증강 중심 모델 최적화 | **4명 전원** 자동 전처리 Pipeline 후보와 학습 데이터 증강 후보를 독립 제안·실행·공유. 5개 모델의 하이퍼파라미터 조정도 병행 | Raw vs Pipeline, 증강 유무, Normal vs Combined를 목적별 통제; 변경 설정·실패·시간·곡선 기록 |
| ④ 후보 5개 비교 및 최종 모델 선정 | 동일 Validation에서 최적 후보 비교 후 1개 선정; Normal Baseline, Combined Baseline, Combined Optimized의 개선 원인 구분 | 작성자·클래스별 성능, Accuracy·Macro F1, 학습/예측 시간, 선택 이유. 필요 시 최종 알고리즘의 Normal Optimized도 추가 비교 |
| ⑤ 모델·전처리 고정 및 자체 평가 | 학습 데이터·파라미터·Pipeline·Seed 확정. **공식 Original Test 16,000장**에서 최종 비교; 별도 신규 Hand-made Test는 선택 | Test 기반 후속 튜닝 금지. Original/Hand-made 성능을 구분; 발표/Notebook에 재현 과정 포함 |
| ⑥ 교수님 1차 Hand-made Test | 완성된 모델에 **고정 Pipeline을 자동 적용**하고 허용된 최종 성능 수치만 확인 | 데이터 개별 이미지·오분류 사례·클래스별 패턴 분석 및 Test에 맞춘 수정 금지. 충분하면 종료 |

## 4. 데이터 종류와 사용 경계

| 데이터 | 확보/상태 | 사용 목적 |
|---|---|---|
| MNIST 0–9 / EMNIST A–F 공식 112,000장 | 확보; Train 96,000 / Test 16,000 | 교수님 구두 설명에 맞춰 공식 Training 내부에서 Train/Val 분리. 기존 Original Test 16,000은 최종 평가까지 보존 |
| 기존 Hand-made 2,560장 (41~44번) | 확보, 이미 탐색 평가 경험 | **개발용** 오류 분석·학습·검증 활용 가능. Combined 학습 편입한 이미지/작성자는 같은 실험의 독립 Validation/Test로 사용 금지 |
| 추가 신규 Hand-made Validation | **640장(8명×80) 권장안 / 수집 전·미확정** | 처음 보는 작성자의 개발 성능 및 모델 선택 확인 |
| 추가 신규 Hand-made Test | **640장(다른 8명×80) 선택안 / 미확정** | 팀 자체 독립 평가 희망 시만 수집. 교수님 Test의 대체 필수조건 아님 |
| 교수님 1차·2차 Hand-made | 교수님 별도 배포 | **Test 전용**. 1차가 충분하면 2차 생략 가능. 어느 쪽도 학습·선별·오류 분석에 이용하지 않음 |

**중요:** ①~④에서 개발 데이터의 오분류 예시·Confusion Matrix·분포를 적극 분석하는 것은 허용된다. **교수님 배포 Test에서는 같은 분석을 하지 않는다.** 원본 Test 이미지 자체의 방향·크기·픽셀을 수동 보정하는 것은 불허하며, 사전에 고정한 자동 Pipeline이 추론 단계에서 동일하게 작동하는 것은 허용된다. 정당한 Cleaning은 별도 지침이 정한 최소한에 한정하고 내용을 모델에 맞춰 수정하지 않는다.

## 5. 데이터 중심 개선 실험의 공통 규칙

- **오류의 원인 후보:** 방향·극성·중심 이탈·글자 크기·획 굵기·명암·잘림·배경 노이즈·클래스/작성자 편차 및 잘못된 레이블. 이미지 문제, 모델 한계, 데이터 분포 차이를 구분한다.
- **전처리 Pipeline:** 분류기 앞에서 모든 입력에 동일한 정책으로 작동하는 이미지 정렬/중심화/크기·명암 조정 등을 후보로 실험한다. 일부 정규화는 오히려 글자의 구분 정보를 지울 수 있으므로 전후 Accuracy, F1, 실패 사례로 판단. Test의 정답·통계·오류로 Pipeline을 학습하거나 수정하지 않는다.
- **Augmentation:** Training 이미지에만 회전·이동·크기·획 굵기 변화를 실험. 증강 원본과 변형본이 Train/Validation에 교차하지 않도록 그룹 단위 분할. 추론 시 무작위 증강을 하는 것과 혼동하지 않는다.
- **데이터 추가:** 기존 2,560장의 단순 수량 증가가 성능 향상을 보장하지 않는다. 독립 작성자 Validation의 실제 개선 여부를 확인한다.
- **모델:** Scikit-learn 범위의 5개 후보를 유지. TensorFlow/PyTorch 기반 NN은 가이드상 금지, Scikit-learn MLP는 사용 가능.
- **분석·보고:** Accuracy, Macro F1, 클래스/작성자별 성능(개발 데이터만), 학습 시간, 추론 시간, 적용한 Pipeline의 처리 시간, Learning Curve. Epoch가 없는 모델에 Epoch를 꾸며내지 말고 학습 크기별 곡선 등 해당 모델에 맞게 제시한다. 각 단계는 실행 결과를 포함하는 Notebook(`.ipynb`)에서도 재현 가능해야 한다.

## 6. 4인 병렬 업무 원칙

팀원 전원은 **매주 각자 (a) 오류·데이터 분석, (b) 전처리 또는 증강 개선 가설, (c) 같은 Validation 기준 전후 성능 평가, (d) 실패를 포함한 로그**를 제출한다. 책임 영역은 병렬로 나누되, '한 사람만 데이터 처리, 나머지는 모델 튜닝만' 하는 방식으로 배정하지 않는다.

구체적인 4인별 병렬 작업 제안, 제출물 체크리스트, 단계별 협업 방식: [TEAM_PARALLEL_WORKPLAN.md](TEAM_PARALLEL_WORKPLAN.md). **담당 집중 영역은 작업계획이며 이미 완료했거나 최종 배정에 합의했다는 주장이 아니다.**
