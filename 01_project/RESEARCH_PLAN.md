# 2026 머신러닝 팀 프로젝트 — 연구계획 (2026-11-10 교수님 직접 답변 반영)

## 1. 목표와 우선순위

대상은 숫자 0–9, 대문자 A–F의 16개 클래스다. 목표는 MNIST·EMNIST에서 잘 학습된 모델이 **처음 보는 필체·위치·기울기·획 굵기**에도 일반화되도록 만드는 것이다.

**우선순위:** (1) 오류 유형과 Original/Hand-made 데이터 분포 차이 분석 → (2) 모든 입력에 동일하게 적용할 자동 전처리 Pipeline·학습용 데이터 증강 검증 → (3) Normal vs Combined 효과 검증·모델별 최적화 → (4) 독립 Test. 높은 Accuracy만으로 완료 처리하지 않고, 원인·가설·실험 설정·전후 결과를 제시한다.

교수님 **최신 개별 답변**에 따라 1차 Hand-made는 최초 Test 후 필요 시 **Validation 전환 가능**, 2차는 **최종 Test 1회 전용**이다. 또한 **Normal과 Combined의 최적 모델을 각각** 선정해야 한다. 기존 PDF·강의의 상충된 지침보다 최신 개별 답변을 우선한다. 세부 흐름은 [RESEARCH_FLOW.md](RESEARCH_FLOW.md)에 기록한다.

## 3. 최신 연구 흐름

**교수님 최신 직접 답변:** Original Test는 이 팀의 공식 구성 기준 **MNIST 10,000장 + EMNIST A–F 6,000장 = 16,000장**으로 사용한다(사용자 확인). **1차 Hand-made는 첫 평가 후 Validation으로 전환 가능**, **2차는 최종 Test로 1회만 사용**한다. Normal과 Combined는 **각각 별도로 최적 모델을 선정**하며 같은 알고리즘일 필요가 없다.

**팀 채택 운영안:** 두 모델을 먼저 선정·고정하고 Original Test 16,000장 → 교수님 1차 Hand-made Test 순서로 평가한다. **1차 성능이 충분하면 그대로 보고서 작성·제출**, 부족할 때에만 1차를 *개발용 Validation*으로 전환해 개선하고 2차에서 한 번 최종 평가한다. 이는 팀이 선택한 1차 활용 전략이며 교수님 답변 자체가 모든 경우의 2차 생략을 명시한 것은 아니다.

**독립성:** 1차를 Validation으로 활용하기 시작하면 수정된 모델에 대한 1차 점수는 독립 Test가 아니다. 2차는 결과 확인 후 다시 튜닝하지 않는다. Original Test도 모델을 선택·튜닝하는 데이터로 사용하지 않고, 모델 버전별 평가 결과를 명확히 기록한다. 자동 입력 Pipeline은 각 평가 전에 고정한 설정으로 실행한다.

[GitHub에서 바로 보는 흐름도 및 설명](RESEARCH_FLOW.md).

| 단계 | 연구 내용 | 실험·보고 원칙 |
|---|---|---|
| ① 기존 Hand-made 오류 분석 | 2,560장의 Confusion Matrix·오분류 사례를 이용해 중심·방향·굵기·기울기·밝기·작성자 편차를 분석 | 기존 데이터는 개발용. 누출 방지, 실제 수치·실패 사례 보존 |
| ② **Normal 독립 최적화** | 공식 MNIST·EMNIST Training만으로 여러 후보 및 전처리·증강·하이퍼파라미터 최적화 | Normal 최적 모델 1개 선정 |
| ③ **Combined 독립 최적화** | 공식 Training + 별도 Hand-made 학습 데이터·추가 수집·증강 등을 조합하고 모델을 독립 선정·최적화 | Combined 최적 모델 1개 선정. 동일 모델 설정에서 데이터 추가 효과를 비교하는 실험은 별도 보조 분석 |
| ④ 최적 모델 2개 고정 | Normal Optimized / Combined Optimized의 파라미터·Pipeline·데이터 버전 동결 | 모델 종류가 서로 달라도 됨. 학습/추론 시간·Accuracy·Macro F1·곡선 기록 |
| ⑤ **Original Test** | **MNIST 숫자 10,000장 + EMNIST A–F 6,000장, 총 16,000장**에서 두 모델 비교 | 모델 선택·수정에 Test를 사용하지 않고 버전·수치를 고정 기록 |
| ⑥ 교수님 **1차 Hand-made Test** | 두 모델을 최초 Test 목적으로 평가 | 만족하면 **추가 최적화 없이 결과 정리·보고서 제출** |
| ⑦ **불만족할 때만** 1차 Validation 전환 | 교수님 허용에 따라 1차 손글씨의 오분류·특성을 개발용 Validation으로 활용하며 전처리·증강·모델 개선 | 1차를 다시 독립 Test라고 부르지 않음. 필요 시 Normal과 Combined 두 모델 재선정·재고정 |
| ⑧ 교수님 **2차 최종 Hand-made Test** | 1차가 부족했던 경로에서 최종 고정 모델을 **한 번만** 평가 | 2차 결과 이후 재튜닝 없이 결과 보고·종료 |

**주의:** ②·③은 병렬적으로 진행할 수 있다. 두 조건의 독립 최적화가 **교수님 요구**이고, 같은 설정의 Normal vs Combined 통제 비교는 데이터 추가 효과 분석을 위한 **선택적인 보조 실험**이다. 최종 모델을 개선한 뒤에는 이전 모델의 Original Test 점수를 개선 모델의 점수로 재사용하지 않는다.

**구분:** 기존 2,560장은 개발용 오류·Confusion Matrix 분석이 가능하다. 교수님 1차는 **최초 Test 평가 시** 모델·Pipeline을 고정하고, **성능이 부족해 Validation으로 전환한 뒤에는** 오분류·이미지 특성 분석과 최적화에 사용할 수 있다. **교수님 2차는 최종 Test 1회 전용**이다. 평가 전에 고정된 자동 Pipeline만 Test 입력에 적용하고 원본 이미지를 수동으로 맞춤 수정하지 않는다.

## 5. 데이터 중심 개선 실험의 공통 규칙

- **오류의 원인 후보:** 방향·극성·중심 이탈·글자 크기·획 굵기·명암·잘림·배경 노이즈·클래스/작성자 편차 및 잘못된 레이블. 이미지 문제, 모델 한계, 데이터 분포 차이를 구분한다.
- **전처리 Pipeline:** 분류기 앞에서 모든 입력에 동일한 정책으로 작동하는 이미지 정렬/중심화/크기·명암 조정 등을 후보로 실험한다. 일부 정규화는 오히려 글자의 구분 정보를 지울 수 있으므로 전후 Accuracy, F1, 실패 사례로 판단. 독립 Test(Original 및 최종 2차)의 정답·오류로 Pipeline을 맞추지 않는다. 1차는 **Validation으로 전환한 이후에만** 개발용 분석·수정에 활용할 수 있다.
- **Augmentation:** Training 이미지에만 회전·이동·크기·획 굵기 변화를 실험. 증강 원본과 변형본이 Train/Validation에 교차하지 않도록 그룹 단위 분할. 추론 시 무작위 증강을 하는 것과 혼동하지 않는다.
- **데이터 추가:** 기존 2,560장의 단순 수량 증가가 성능 향상을 보장하지 않는다. 독립 작성자 Validation의 실제 개선 여부를 확인한다.
- **모델:** Scikit-learn 범위의 5개 후보를 유지. TensorFlow/PyTorch 기반 NN은 가이드상 금지, Scikit-learn MLP는 사용 가능.
- **분석·보고:** Accuracy, Macro F1, 클래스/작성자별 성능(개발 데이터만), 학습 시간, 추론 시간, 적용한 Pipeline의 처리 시간, Learning Curve. Epoch가 없는 모델에 Epoch를 꾸며내지 말고 학습 크기별 곡선 등 해당 모델에 맞게 제시한다. 각 단계는 실행 결과를 포함하는 Notebook(`.ipynb`)에서도 재현 가능해야 한다.

## 6. 4인 병렬 업무 원칙

팀원 전원은 **매주 각자 (a) 오류·데이터 분석, (b) 전처리 또는 증강 개선 가설, (c) 같은 Validation 기준 전후 성능 평가, (d) 실패를 포함한 로그**를 제출한다. 책임 영역은 병렬로 나누되, '한 사람만 데이터 처리, 나머지는 모델 튜닝만' 하는 방식으로 배정하지 않는다.

**팀원별 세부 업무 분담과 병렬 진행 일정은 팀장이 별도로 작성할 예정이다. 저장소에서 사전 배정표는 제거한다.**

### 작성자 그룹 CV와 추가 손글씨 수집: 후속 선택지

- 교수님은 제출한 기존 2,560장 외에 **손글씨를 추가 작성·수집하여 학습 데이터로 보강하는 것**도 허용했다. 새로운 필체·기울기·크기·획 굵기 등 기존 분포의 부족한 부분을 보완할 수 있는지 평가하며 수집 수량·학습/검증 사용처는 미확정이다.
- 신규 작성자 Validation이 없고 기존 2,560장으로 Combined 학습과 검증을 모두 해야 한다면 **실제 작성자 기준 Group CV/Leave-One-Writer-Out**를 검토한다. 41·42·43·44 파일이 각기 서로 다른 한 명이 작성했다는 전제에서만 4-Fold(Hand-made Training 1,920장/Validation 640장)가 성립한다. 한 파일에 여러 작성자가 있다면 실제 작성자 ID로 그룹을 분리한다.
- 각 Fold에서 Normal은 동일 공식 데이터만 학습하고, Combined는 동일 공식 데이터 + **보류 그룹을 제외한 Hand-made 학습분만** 사용해 다시 학습한다. 같은 보류 Validation과 설정으로 Accuracy·Macro F1을 비교하고 Fold 평균·편차를 보고한다. 원본·증강본/작성자 누출 금지. 기존 2,560장은 이미 개발에 사용했으므로 CV 결과는 **독립 Test가 아닌 개발용**이다.
- 신규 작성자 Validation을 별도로 확보하면 기존 2,560장을 Combined Training에 모두 포함하고 독립 신규 Validation으로 비교할 수 있어, 기존 2,560장 내부 CV가 **반드시 필요한 것은 아니다**. CV 선택 및 추가 수집은 미확정 상태다.

## 7. 코드와 재현성

[5개 학습 전 기본 모델 코드](../03_experiments/model_optimization/README.md)는 **현재 공식 데이터에 대한 Normal Baseline/Candidate 학습용**이다. **Combined, 이미지 Pipeline, 증강 실험 기능은 아직 구현되지 않았다**; 후속 작업 시 공통 함수와 실행 경로를 확장해야 한다. 동일한 원본 실험 2 결과가 새 코드로 전체 재현됐다고 표시하지 않는다. 기존 실험일지·CSV·NPZ는 변경하지 않는다.
