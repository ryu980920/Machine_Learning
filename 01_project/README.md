# 01_project — 프로젝트 운영 및 진행 기록

## 1. 개요

수행계획서 작성, 역할 분담, 회의 내용과 전체 진행 상황을 관리합니다. 팀이 언제 무엇을 결정했고 각자가 어떤 작업을 했는지 남겨 수행일지와 최종보고서에 활용합니다.

## 2. 작업 내용

- 프로젝트 목표와 전체 진행 순서를 정리하고 팀 수행계획서(약 1–2쪽)를 작성합니다.
- 팀원별 담당 업무, 기한 및 공유해야 할 결과물을 합의합니다.
- 회의 날짜·참석자·논의 내용·결정 사항·다음 회의 전 할 일을 기록합니다.
- 일정 또는 역할을 변경하면 변경 이유와 합의한 내용을 남깁니다.
- 팀원별 실제 작업과 결과물이 연결되도록 수행 내역을 관리합니다.

## 7. 최신 계획과 모든 팀원의 병렬 참여 — 2026-11-10

- [전체 연구계획](RESEARCH_PLAN.md): ① 4인 공통 오류·데이터 분석 → ② Normal/Combined 효과 검증 → ③ 자동 Pipeline·증강 중심 최적화 → ④ 5개 비교·최종 모델 확정 → ⑤ Original Test → ⑥ 교수님 1차 Test → ⑦ 필요 시 2차 Test.
- 팀원별 세부 업무 분담과 일정을 포함한 병렬 실행계획은 팀장이 직접 작성할 예정이며, 현재는 별도 담당 배정을 확정하지 않는다.
- [의사결정 이력](DECISION_LOG.md): 교수님 구두 Test 정정, 기존 PDF와 구별된 운영 규칙, 완료/미실시 판단.
- [Hand-made 데이터 분할 및 Test 정책](../02_data/HANDMADE_SPLIT_PLAN.md): 기존 2,560장 학습/검증 허용(누출 불가), 신규 Validation 640장은 수집 권장안, 신규 독립 Test 640장은 선택안.
- [학습 전 5개 모델 코드](../03_experiments/model_optimization/README.md): 기존 Baseline 재현용이며 Combined/Pipeline/증강 기능은 **향후 구현 과제**.

**교수님 최신 직접 답변 반영:** 1차 Hand-made는 두 최적 모델을 먼저 고정해 **최초 Test로 평가**한다. 성능이 충분하면 그대로 보고하며, 부족하면 **1차 데이터를 Validation으로 전환해 오분류·특성 분석 및 추가 최적화에 활용 가능**하다. 이후 모델과 자동 Pipeline을 다시 고정해 **2차 Hand-made를 최종 Test로 한 번만 평가**한다. Original Test 16,000장과 2차 Test는 모델 튜닝에 사용하지 않는다.

**상태:** W02 실험 1~3 수행 기록 보존, 이후 Combined 재학습·자동 Pipeline/증강 실험·외부 Test는 아직 미실시.

**역할 배정:** 별도의 병렬 작업 제안 문서는 삭제한다. 구체적인 팀원별 업무·담당 모델·일정은 팀장이 직접 작성한다. 원칙적인 데이터·오류 분석의 중요성은 [연구계획](RESEARCH_PLAN.md)에만 남긴다.

## 8. 교수님 직접 답변 이후 확정 흐름 (2026-11-10)

[확정 흐름도(자동 렌더링 Mermaid)](RESEARCH_FLOW.md) · [최신 연구계획](RESEARCH_PLAN.md) · [결정 이력](DECISION_LOG.md).

- Normal·Combined **각각** 최적 모델을 찾아 두 개 고정한다. 두 모델은 동일 알고리즘일 필요가 없다.
- **Original Test 16,000장 → 교수님 1차 Test** 순서로 평가한다. 1차가 충분하면 수정 없이 보고서 제출.
- 1차가 미흡할 때에만 **1차 Validation 전환 → 모델 보완·재고정 → 2차 최종 Test 단 1회**로 진행한다.
- 상세 팀원별 역할·일정은 팀장이 별도로 작성하며 이전과 같이 임의 배정하지 않는다.
